9.1Coordinator

Answers: Q9.1 to Q9.4, Q9.7, Q9.8, Q9.11

Figure 1. Layer 9 at a glance. The code coordinator is the hub. It sends each task to one agent or code function and reads back a typed output. Agents never call each other. When the diagnoser or the critic needs more evidence, the hub sends the request to the investigator. The investigator and the fixer run a tool loop. The budgets stop every loop. Every write passes the gates outside the agents.

What an agent is in this platform

TermMeaningQLabel
AgentA large language model (LLM: it generates text one token at a time) plus typed tools, a control loop, saved state and a goal. The model only requests a tool call. The application runs the call.Q9.1, Q9.2Decision
CoordinatorDeterministic application code that runs the loop. It decides the next step. It enforces the budget, the limits and the stop rules. No model is the orchestrator.Q9.7Decision

An investigation is not a chat session. One durable IncidentWorkflow (A8) holds the whole process. Each model call is one bounded activity with a structured output (Q9.3). One agent for every job is unreliable (Q9.11). An error in one step flows into every later step, and no part checks it. The agent would approve its own work. One injected instruction would control the whole chain. So the platform uses several agents with narrow jobs, and code coordinates them.

How the coordinator selects the next step

The coordinator uses no model to route. Each agent ends its run with one typed output. The type and its values select the next step. The model decides what it needs. Code decides who supplies it. Before each step, code checks the budgets (section 9.10). A budget that runs out sends the incident to Escalated.

The coordinator loop

Figure 2. The coordinator loop. It has no round limit. The investigator calls read tools until it returns tested hypotheses. The diagnoser returns a diagnosis or an evidence request. The coordinator sends an evidence request to the investigator and then calls the diagnoser again. A diagnosis must pass the evidence rule before the critic sees it. A revise verdict returns once: to the investigator first when evidence is missing, then to the diagnoser. Every other exit ends in escalation, and the budgets can stop the loop at any step.

Correlation is not causation

A change just before the incident is a hypothesis, not a cause (Q9.26). The change hypothesis must pass the four checks of A3 Figure 5: timing, location, mechanism and dependencies. The competing hypothesis, for example a database failure, is tested with dependency metrics at the same time. Only the verified recovery confirms the cause.

9.8Critic schema

Answers: Q9.30 to Q9.32, Q9.36, Q9.37

The critic uses a different model in a new context (A1, A5 SC-12). It reads the diagnosis claims, the cited evidence summaries and the ruled-out hypotheses. It does not read the diagnoser's reasoning, so it judges the result, not the argument (Q9.30).

Output fieldContentLabel
verdictaccept, revise, escalate or no_verdict. The model gives one of the first three. Code records no_verdict for an invalid output (section 9.3), and the incident escalates (Q9.37). The verdict is a check_result row with kind = critic. The other kinds (policy, sandbox, verification) are in A7 and A8.Decision Q9.32
findingsOne finding for each claim: supported, unsupported or contradicted, with the evidence IDs it checked.Decision Q9.31
missing_evidenceEvidence the critic wants. The coordinator sends it to the investigator (section 9.9).Decision Q9.34
reasonShort text for the human. findings, missing_evidence and reason are kept in check_result.detail.Decision Q9.32
Criteria for a diagnosisCriteria for a fix
  1. Each claim is supported by its cited evidence.
  2. The evidence says what the claim says.
  3. The alternatives were tested and ruled out with a reason.
  4. Every contradiction is explained.
  5. The required sources are present.
  6. The causation checks passed (section 9.6).
  7. The confidence fits the evidence.
  1. The diff matches the diagnosis.
  2. The diff stays in the service repository and under the size limit.
  3. The fix has an undo path.
  4. The test plan reproduces the fault (A4 FR-09).
RuleLabel
"Signal only" works in one direction. An accept never lets an action skip the policy gate or the human approval. A revise or escalate can stop the automatic path.Decision Q9.30 (reading of A5 SC-12)
Agreement between two models is not ground truth (Q9.36). Both models see the same inputs, so their errors are linked. Evidence can be stale, incomplete or planted. So the critic checks the evidence, not only the conclusion. Ground truth comes only from the verification and from human feedback (section 9.11).Decision Q9.36
