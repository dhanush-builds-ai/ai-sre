9.1Coordinator

Answers: Q9.1 to Q9.4, Q9.7, Q9.8, Q9.11

Figure 1. Layer 9 at a glance. Code collects the baseline evidence and applies the fixed rules. Three agents then investigate, diagnose and review. Code maps the cause to a recovery action, and every write passes the gates outside the agents. Hard limits stop the loop, and labelled simulations in the dummy application measure the result.

What an agent is in this platform

TermMeaningQLabel
Large language model (LLM)A model that generates text. It predicts the next token from the input tokens, one token at a time. V1 uses a cloud model provider by default. Self-hosted open-weight models are an option by configuration. All calls go through the one inference gateway.Q9.1Fixed requirement A2 2.1, A6 ADR-06
AgentAn LLM plus typed tools, a control loop, saved state and a goal. The model only requests a tool call. The application runs the call.Q9.2Decision
CoordinatorDeterministic application code that runs the loop. It decides the next step. It enforces the budget, the limits and the stop rules. No model is the orchestrator.Q9.7Decision
SkillA versioned unit of behavior with typed input and output (section 9.2). A skill is either code or one PydanticAI agent.Q9.13Decision

An investigation is not a chat session. One durable IncidentWorkflow (A8) holds the whole process. Each model call is one bounded activity with a structured output (Q9.3). One agent for every job is unreliable (Q9.11). An error in one step flows into every later step, and no part checks it. The agent would approve its own work. One injected instruction would control the whole chain. So the platform uses several agents with narrow jobs, and code coordinates them.

The coordinator loop

Figure 2. The coordinator loop. The investigator runs at most 3 rounds. A diagnosis must pass the L9-A4 evidence rule before the critic sees it. A revise verdict returns to the diagnoser at most twice. Every other exit ends in escalation, and hard limits can stop the loop at any step.

9.4Tool registry

Answers: Q9.5, Q9.6, Q9.9, Q9.10, Q9.39 to Q9.47

Figure 6. One tool call through the tool layer. The checks run in order before any outside call. The result is redacted, checked for injected instructions and recorded. The agent then gets only a short summary marked as untrusted. No agent can reach a write, a shell, a production host or a credential.

Correlation is not causation

A change just before the incident is a hypothesis, not a cause (Q9.26). The change hypothesis must pass every check below. The competing hypothesis, for example a database failure, is tested with dependency metrics at the same time. Only the verified recovery confirms the cause.

Check (A3 Figure 5)Disproves the change hypothesis when
TimingThe errors started before the change, or long after it with no other link.
LocationThe errors appear where the change does not apply (other instances, other endpoints).
MechanismThe logs show no link to the changed key, code path or version.
DependenciesA dependency of the service failed at the same time (for example, the database).

9.8Critic schema

Answers: Q9.30 to Q9.32, Q9.36, Q9.37

The critic uses a different model in a new context (A1, A5 SC-12). It reads the diagnosis claims, the cited evidence summaries and the ruled-out hypotheses. It does not read the diagnoser's reasoning, so it judges the result, not the argument (Q9.30).

Output fieldContentLabel
verdictaccept, revise or escalate. An invalid output after 3 attempts is recorded as no_verdict (Q9.37).Decision Q9.32
findingsOne finding for each claim: supported, unsupported or contradicted, with the evidence IDs it checked.Decision Q9.31
missing_evidenceRead queries the critic wants run. The coordinator runs them through the tool layer (section 9.10).Decision Q9.34
reasonShort text for the human.Decision Q9.32
Criteria for a diagnosisCriteria for a fix
  1. Each claim is supported by its cited evidence.
  2. The evidence says what the claim says.
  3. The alternatives were tested and ruled out with a reason.
  4. Every contradiction is explained.
  5. The required sources are present.
  6. The causation checks passed (section 9.6).
  7. The confidence fits the evidence.
  1. The diff matches the diagnosis.
  2. The diff stays in the service repository and under the size limit.
  3. The fix has an undo path.
  4. The test plan reproduces the fault (A4 FR-09).
RuleLabel
"Signal only" works in one direction. An accept never lets an action skip the policy gate or the human approval. A revise or escalate can stop the automatic path.Decision Q9.30 (reading of A5 SC-12)
Agreement between two models is not ground truth (Q9.36). Both models see the same inputs, so their errors are linked. Evidence can be stale, incomplete or planted. So the critic checks the evidence, not only the conclusion. Ground truth comes only from the verification and from human feedback (section 9.11).Decision Q9.36
A8 requires a recorded critic review before diagnosed. A no_verdict result escalates.Fixed requirement A8 8.4
