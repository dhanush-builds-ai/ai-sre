8.1Temporal workflow definition

Answers: Q8.1 to Q8.3, Q8.5, Q8.6, Q8.10, Q8.12 to Q8.16, Q8.24

An investigation takes minutes to hours and waits up to 24 h for a human. A normal Python function keeps its progress in process memory. The table shows what fails, and what the platform uses instead.

8.3State machine diagram

Answers: Q8.25, Q8.26, Q8.39

Two state machines work together. The incident machine is for people and has 7 states. The action machine runs once for each child workflow and holds the detail. PostgreSQL owns both states (Q8.39). Only workflow activities change them. A CHECK constraint lists the allowed values.

Figure 2. Incident state machine. queued is the initial state (Q8.26). resolved and cancelled are end states. Every hand-over to humans goes to one state, escalated; the event that caused it holds the reason. Lines that cross without an arrow do not connect.

Figure 3. Action state machine (one per child workflow). verified, blocked, rejected, expired, cancelled, failed and not_recovered are end states. proposed and testing can also go to cancelled. An action in outcome_unknown past its limit stays there, and its incident goes to escalated.

8.5Retry and timeout policies

Answers: Q8.14, Q8.17, Q8.18, Q8.40, Q8.41, Q8.43, Q8.44

One retry owner

Activities run at least once (Q8.40). The platform never uses at most once for incident work (Q8.41); the only exception is an SSE update, which the client gets again on reconnect. Retry layers multiply: three layers of 3 attempts send 27 calls to a failing server (Q8.43). So only the Temporal activity retry policy retries (Q8.44). Decision

LayerRetry setting
Temporal activityThe only retry. Values in the table below.
Model SDK clientmax_retries=0 (the OpenAI SDK default is 2).
HTTP clientsTransport retries off.
Inference gatewaySends each request once. No fallback to another model or provider (A2).
APINever retries workflow work. Its only retry is the admission loop's workflow start, which is idempotent (A7 7.7).

Values for each activity

Every retry waits 1 s first, doubles each time, and never waits more than 60 s. Validation errors, policy rejections, 401 and 403 are not retried. A schedule-to-start timeout means no worker took the task; the workflow escalates the incident and raises a platform alert (Q8.14). Assumption L8-A3 for the values.

Guards before applying (Q8.29)

The executor checks all of these just before dispatch. If any guard fails, nothing is dispatched.

  1. The decision is approve, and its signature is valid.
  2. The approver is eligible: approver role; not the author of a fix (M11); not an admin account (A5 SC-04).
  3. The action hash in the approval equals the current action hash.
  4. The approval is still valid (section above).
  5. The approval is not used yet (approval_use, single use, A5 SC-14).
  6. The precondition still holds (for example, the current config is v42).
  7. The incident is not cancelled and no cancel is pending.
  8. No other action on the same target is in applying or outcome_unknown.

Answers: Q8.22, Q8.36, Q8.37

Cancel is the signal cancel(reason, user_id), not Temporal cancellation. Temporal cancellation reaches every running activity, including a production write. The workflow acts on the signal only at safe points. A second cancel does nothing (A7 7.8). Decision

8.8Replay strategy

Answers: Q8.2, Q8.4, Q8.5, Q8.7 to Q8.9, Q8.13, Q8.23, Q8.24

After a crash, local variables are lost (Q8.4). A new worker runs the workflow code again from the start. For each recorded step, the engine gives the recorded result and does not run the activity again. The code reaches the same point with the same variables (Q8.8). Replay works only if the workflow code is deterministic.

8.9Reconciliation strategy

Answers: Q8.11, Q8.32 to Q8.34, Q8.39, Q8.42, Q8.45, Q8.48

Exactly-once execution of an outside effect is not possible over a network. The caller cannot tell a lost request from a lost reply, and the outside system is not in our transaction (Q8.42). The platform gets an effectively-once result: at-least-once delivery, an idempotency key, and an idempotent target. "Set config to v41 only if it is v42" does nothing the second time. "Redeploy artifact X" does nothing when X already runs. Decision
