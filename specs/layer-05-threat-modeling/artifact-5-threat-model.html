5.4Trust boundaries

Answers: Q5.2, Q5.12, Q5.13, Q5.17, Q5.18, Q5.19

A trusted component enforces a security rule. An untrusted component can be wrong or hostile, so a trusted component must check its output. The model is untrusted. This is true for the agent model and for the reviewer model. The reviewer's verdict is a signal. It is never an authorization.

5.6Security controls

Answers: Q5.1 to Q5.11, Q5.13 to Q5.28

A control is valid only if it is enforced outside the model. A rule in the prompt is not a control. The executor and the approval gate are plain code. The model cannot change them.

Decision (M11, Q5.7). The author of the change that caused the incident can approve the revert or the config restore. The target is a version that already passed staging and QA. At 2 AM the author is often the only person on call. The author must not approve the permanent fix. A different person must approve and merge the fix pull request. Reason: an insider can plant text in their own code or logs to steer the AI patch, and then approve it alone. The fix is not urgent, because the service is already recovered and the fix approval is valid for 24 h (QR-05).
